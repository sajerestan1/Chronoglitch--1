# Production workflow

This workflow adapts the gate-based CloneVoice + VideoExpress reference for Chronoglitch, a consistent 3D speaking host. It does not assume any particular app integration, control, exact lip sync or browser capability. Check the current tools before production.

## One-time setup
- Keep the canonical image at `assets/character/approved-concept.png` and accepted design references in `assets/character/`.
- Create a separate episode folder by copying the brief, claim ledger, scene plan and production ledger templates.
- Choose one authorized voice and keep a pronunciation guide. Never store voice samples or credentials in project notes.
- Check available image, animation/video, voice/TTS, audio and editing tools. Record model/version, limits, privacy, license/usage terms, export settings and expected costs in the episode ledger.
- Approve any reusable wardrobe variants. Make one short proof scene before batching.

## Gates
### 1. Brief, research and claims
Define topic, geography, dates, audience, runtime, aspect ratio and tone in the episode brief. Research primary sources when practical plus reputable archives, museums, academic and specialist works. Record each claim, source URL, page/section, access date and status. Separate facts, interpretations and disputes. AI output is not evidence. Verify names, dates, numbers, quotations, maps and causal claims. Check period details against sources. Freeze the script before narration; any later factual edit updates script, audio, timings and ledger.

### 2. Voice and scene plan
Create one complete performance using the same authorized voice. Check pronunciation, pace, emphasis, clipping and facts. Split into visual beats in `scene-plan.csv`, not automatically one sentence per row. Mark each beat on-camera, voiceover cutaway or silent and record actual audio in/out time. Use final audio to drive lip sync only when supported. Lock timings before rendering.

### 3. References and proof
Use the supplied Chronoglitch source as canonical. Prepare only needed model, expression, mouth/viseme and wardrobe sheets; compare them to the source and identity locks. Generated sheets remain proposals until checked. Render one short proof scene and check identity, mouth movement, sync, historical detail, framing, privacy and quality. Get creator review before a full batch.

### 4. Create and review scenes
Generate stills using accepted references and the chosen role variant. Keep the identity block fixed; describe scene action separately. Animate accepted stills only. Use final audio for dialogue when supported; cutaways carry narration without a visible talking face. Add accurate labels and citations in the editor, not generated text. Record generation ID, model, prompt version, input reference, audio range, duration and status. Preview for identity, lip sync, movement, anatomy, text artifacts, history accuracy and privacy. After interruption, inspect the media library and ledger before regenerating.

### 5. Assemble and export
Arrange accepted scenes against master narration. Keep speech clear; use licensed music only if it leaves room for speech. Add titles, maps, labels, captions, dates and source credits in the editor. Review pacing, continuity, unsupported claims and identity drift. Export at chosen ratio/resolution and watch the export itself. Confirm duration, sound and end card. Save the editable project and record export details.

## Historical and respectful visuals
Keep sequences within a clear date range and place. Mark modern borders as modern. Do not flatten a culture or make separate eras appear simultaneous. Name communities when supported by sources. For violence, forced migration, slavery, colonialism or persecution, name coercion and use sober visuals. Label reconstructions if viewers might mistake them for footage. Cite images, maps, music and footage as well as historical claims.

## Recovery and completion
After interruption, reread the ledger and inspect the tool's media library before generating again. Resume at the first unfinished beat. A queued generation is not accepted until previewed. Completion requires an approved script and claims, checked voice, frozen scene plan, accepted references, accepted asset or explicit editorial replacement for every beat, assembled watched export, and saved project/source notes.
